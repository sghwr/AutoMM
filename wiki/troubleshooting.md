# 排错与扩展

## Runner 一直 idle

检查是否已初始化活动题目、是否处于 PAUSE/STOP、当前小问 manifest 是否已有满足阶段的产物，以及 `next-action` 的 reason。idle 可能是正常等待，不应通过手改状态强迫推进。

## Agent 调用失败

先运行 provider capability probe，确认 CLI 登录、`exec` 和 schema 参数可用；再看 `runtime/actions/<action_id>/stderr.log`。常见原因是超时、最终消息不是纯 JSON、缺少必需数组、action ID 或上下文不匹配、产物路径不存在、命令不在白名单。

Agent 已创建正确文件但响应失败时，先保留产物并由下一次恢复对账，不直接重放所有动作。修改 prompt 时优先澄清输入/输出契约，不堆叠重复全局规则。

## 任务无法启动

确认 `.venv` 已安装 `ruff` 和 requirements；代码能 compile；输入、配置、版本目录存在；公式版本已接受；输出位于正确版本目录；命令使用当前 Python。重复 ID、并发无槽位和输出目录冲突都会阻止启动。

## 结果异常

进程成功但数值异常属于 sanity 问题。检查单位、数据列、归一、约束残差、边界、随机种子和求解器状态，按归属回退。不要通过无限重跑寻找“看起来合理”的随机结果。

## 图表失败

自动失败时看同名 `.quality.json`；检查尺寸、空白、裁切和文件格式。视觉失败时检查字体是否存在、中文是否显示、图例/标签是否重叠、单位和数据方向是否一致。所有脚本必须使用统一配置。

## 文献无法核验

核对 DOI/标题/作者，尝试 Crossref 与 OpenAlex；区分网络错误和确实无记录。无法核验的来源保留 pending/rejected，不能用于关键假设。更换为权威来源或降低主张强度。

## 邮件或远端失败

先做只读认证和最小连接测试。邮件检查服务器、端口、TLS、应用密码和白名单；SSH 检查 DNS、主机指纹、密钥/密码、工作目录和权限；Kaggle 检查 API key、配额和资源状态；GitHub 检查私有仓库权限和同步清单。日志必须脱敏。

## 跨平台问题

路径使用 `pathlib` 和相对路径，子进程传参数列表并保持 `shell=False`。不要依赖 Bash、驱动器盘符或大小写敏感行为。文本统一 UTF-8；Windows 上额外检查 PowerShell 激活、长路径、进程组和中文字体。

## 扩展新方法

优先向 Knowledge 增加方法条目，让现有 Agent 按适用性选择。只有出现新的生命周期、权限或产物类型时才扩展 Skill/Agent。新增计算后端应实现认证、push、submit、poll、pull、verify、cancel/recover 的统一接口，并给出明确失败状态。

新增阶段会扩大状态机，应同时更新阶段枚举、迁移表、next-action、registry、产物门禁、恢复规则和测试。没有真实需求时不要增加预留阶段。

## 验收原则

每个扩展至少验证正常路径、输入无效、依赖不可用、进程中断、重复调用、恢复和跨平台。网络功能还需验证认证失败、超时、幂等和敏感信息脱敏。完成条件以可复现产物和机器状态为准，不以一次聊天回答为准。
